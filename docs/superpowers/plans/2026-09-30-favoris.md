# Favoris — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pouvoir mettre en favori une œuvre, un personnage ou un membre du staff, et afficher ces favoris sur le profil `/u/[username]`, comme AniList.

**Architecture:** Une table `Favorite` (une ligne par couple utilisateur × cible AniList). Une œuvre pointe vers le miroir `Media` (garanti par `ensureMediaMirror`) ; un personnage ou un staff garde un instantané `name` / `image` pris au like. Nouvelle feature `src/features/favorites/` : schéma Zod, fonction pure de regroupement, lectures server-only, une Server Action `setFavorite`, un bouton client optimiste. Le profil lit tout en base, sans AniList.

**Tech Stack:** Next 16 (App Router, `cacheComponents`), Prisma 7, next-safe-action v8, Zod 4, Vitest, shadcn/ui, lucide-react, sonner.

**Spec:** [docs/superpowers/specs/2026-09-30-favoris-design.md](../specs/2026-09-30-favoris-design.md)

## Global Constraints

- Toutes les règles de `CLAUDE.md` : `src/app/` = routing seul ; `import "server-only"` pour les lectures, `"use server"` pour les actions ; action via `authActionClient`, `.metadata()` puis `.inputSchema()` ; aucune URL en dur (`routes`) ; `prisma` depuis `@/lib/db/prisma` ; types par `z.infer` ; fichiers en kebab-case ; pas de barrel.
- `"use client"` seulement sur `favorite-button.tsx`.
- Aucune lecture AniList sur le profil.
- Image d'un personnage/staff acceptée seulement si elle commence par `https://s4.anilist.co/file/` (le seul hôte autorisé par `next.config.ts`), sinon refusée par le schéma.
- Le filtre 18+ du profil suit les préférences de **celui qui regarde** (`getPreferences().includeAdult`), appliqué dans le `where`.
- Ordre d'affichage : `createdAt desc`.
- Commentaires en français, au ton et à la densité du code voisin.
- **Écart assumé avec la spec** : l'action s'appelle `setFavorite` et reçoit l'état voulu (`favorite: boolean`) plutôt que de basculer — un double clic ou deux onglets ne peuvent plus inverser deux fois. La spec est corrigée dans la tâche 1.

```ts
import * as z from "zod";

/**
 * Ce qu'on met en favori, et l'état qu'on veut lui donner.
 *
 * **Une personne voyage avec son instantané** — nom et portrait —, parce qu'elle n'existe pas en
 * base : c'est ce qu'affichera le profil, sans requête AniList. Le client l'a déjà sous les yeux ;
 * le cercle étant privé, on lui fait confiance pour le texte, mais pas pour l'adresse de l'image,
 * qui ne peut venir que du CDN d'AniList — le seul hôte que `next.config.ts` laisse charger.
 */

const ANILIST_IMAGE_PREFIX = "https://s4.anilist.co/file/";

const anilistIdSchema = z.number().int().positive();

const mediaTargetSchema = z.object({
  kind: z.literal("MEDIA"),
  anilistId: anilistIdSchema,
});

const personTargetSchema = z.object({
  kind: z.enum(["CHARACTER", "STAFF"]),
  anilistId: anilistIdSchema,
  name: z.string().trim().min(1).max(200),
  image: z
    .url()
    .refine((url) => url.startsWith(ANILIST_IMAGE_PREFIX), {
      message: "Image hors AniList.",
    })
    .nullable(),
});

export const favoriteTargetSchema = z.discriminatedUnion("kind", [
  mediaTargetSchema,
  personTargetSchema,
]);

export type FavoriteTarget = z.infer<typeof favoriteTargetSchema>;
export type FavoriteKind = FavoriteTarget["kind"];

/**
 * **L'état voulu, pas une bascule.** Deux clics rapides, ou deux onglets, enverraient deux
 * « bascule » qui s'annulent ; deux « favori : oui » laissent la même ligne.
 */
export const setFavoriteSchema = z.object({
  target: favoriteTargetSchema,
  favorite: z.boolean(),
});

export type SetFavoriteInput = z.infer<typeof setFavoriteSchema>;
```

```ts
import { mirroredTitle } from "@/features/media/lib/media-format";
import type { TitleLanguage } from "@/features/preferences/schemas/preferences.schema";

/**
 * Les favoris d'un membre, rangés comme AniList les montre : anime, manga, personnages, staff.
 *
 * Pure et testée à part : la lecture (`favorites.queries.ts`) ne fait que ramener les lignes dans
 * l'ordre voulu, et c'est ici que se décide dans quel bloc chacune tombe. L'ordre reçu est gardé
 * tel quel — c'est la requête qui trie, les plus récents d'abord.
 */

export type FavoriteRow = {
  kind: "MEDIA" | "CHARACTER" | "STAFF";
  anilistId: number;
  name: string | null;
  image: string | null;
  media: {
    type: "ANIME" | "MANGA";
    titleRomaji: string | null;
    titleEnglish: string | null;
    titleNative: string | null;
    coverImage: string | null;
  } | null;
};

/** Une vignette du profil : de quoi afficher une image, un nom, et construire le lien. */
export type FavoriteTile = { id: number; name: string; image: string | null };

export type FavoriteGroups = {
  anime: FavoriteTile[];
  manga: FavoriteTile[];
  characters: FavoriteTile[];
  staff: FavoriteTile[];
};

export function groupFavorites(
  rows: FavoriteRow[],
  titleLanguage: TitleLanguage,
): FavoriteGroups {
  const groups: FavoriteGroups = {
    anime: [],
    manga: [],
    characters: [],
    staff: [],
  };

  for (const row of rows) {
    if (row.kind === "MEDIA") {
      // Une clé étrangère en cascade rend le cas impossible en base ; on le traite quand même
      // plutôt que d'afficher une vignette sans titre.
      if (!row.media) continue;

      const tile = {
        id: row.anilistId,
        name: mirroredTitle(row.media, titleLanguage),
        image: row.media.coverImage,
      };
      (row.media.type === "ANIME" ? groups.anime : groups.manga).push(tile);
      continue;
    }

    const tile = {
      id: row.anilistId,
      name: row.name ?? "Sans nom",
      image: row.image,
    };
    (row.kind === "CHARACTER" ? groups.characters : groups.staff).push(tile);
  }

  return groups;
}

export function isEmptyFavorites(groups: FavoriteGroups): boolean {
  return Object.values(groups).every((tiles) => tiles.length === 0);
}
```

```ts
import "server-only";

import {
  type FavoriteGroups,
  groupFavorites,
} from "@/features/favorites/lib/favorites-groups";
import type { FavoriteKind } from "@/features/favorites/schemas/favorites.schema";
import type { TitleLanguage } from "@/features/preferences/schemas/preferences.schema";
import { getSession } from "@/lib/auth/session";
import { prisma } from "@/lib/db/prisma";

/**
 * Les lectures des favoris — **toutes en base**, comme le reste du profil.
 *
 * Aucun `"use cache"`, pour la raison de `profile.queries.ts` : ce qu'on lit dépend du membre
 * regardé, et le filtre 18+ de celui qui regarde.
 */

/** L'état initial du cœur : cette cible est-elle dans **mes** favoris ? */
export async function isFavorite(
  kind: FavoriteKind,
  anilistId: number,
): Promise<boolean> {
  const session = await getSession();

  if (!session) {
    throw new Error("Lecture de favori hors de la garde de `app/(app)/layout.tsx`.");
  }

  const row = await prisma.favorite.findUnique({
    where: {
      userId_kind_anilistId: { userId: session.user.id, kind, anilistId },
    },
    select: { id: true },
  });

  return row !== null;
}

/**
 * Les favoris d'un membre, rangés pour son profil.
 *
 * Le filtre 18+ porte sur le miroir et ne touche que les œuvres : un personnage ou un staff n'a
 * pas de classement adulte chez AniList.
 */
export async function getProfileFavorites({
  userId,
  includeAdult,
  titleLanguage,
}: {
  userId: string;
  includeAdult: boolean;
  titleLanguage: TitleLanguage;
}): Promise<FavoriteGroups> {
  const rows = await prisma.favorite.findMany({
    where: {
      userId,
      ...(includeAdult
        ? {}
        : { OR: [{ kind: { not: "MEDIA" } }, { media: { isAdult: false } }] }),
    },
    orderBy: { createdAt: "desc" },
    select: {
      kind: true,
      anilistId: true,
      name: true,
      image: true,
      media: {
        select: {
          type: true,
          titleRomaji: true,
          titleEnglish: true,
          titleNative: true,
          coverImage: true,
        },
      },
    },
  });

  return groupFavorites(rows, titleLanguage);
}
```

```ts
  switch (target.kind) {
    case "MEDIA":
      return routes.media(target.anilistId);
    case "CHARACTER":
      return routes.character(target.anilistId);
    case "STAFF":
      return routes.staff(target.anilistId);
  }
}

/**
 * Mettre en favori, ou retirer.
 *
 * - **L'état voulu, pas une bascule** (`favorites.schema.ts`) : `upsert` quand on ajoute,
 *   `deleteMany` quand on retire — deux gestes identiques laissent la base dans le même état.
 * - **`ensureMediaMirror` avant d'écrire une œuvre**, pour la même raison que les listes :
 *   `Favorite.mediaId` est une clé étrangère vers le miroir, et l'on peut aimer une œuvre que
 *   personne n'a jamais suivie.
 * - **Un personnage ou un staff rafraîchit son instantané** à chaque nouveau like : c'est la seule
 *   occasion qu'on a de rattraper un portrait changé chez AniList.
 */
export const setFavorite = authActionClient
  .metadata({ actionName: "setFavorite" })
  .inputSchema(setFavoriteSchema)
  .action(async ({ parsedInput: { target, favorite }, ctx }) => {
    const userId = ctx.user.id;
    const { kind, anilistId } = target;

    if (!favorite) {
      await prisma.favorite.deleteMany({ where: { userId, kind, anilistId } });
    } else if (target.kind === "MEDIA") {
      await ensureMediaMirror(anilistId);
      await prisma.favorite.upsert({
        where: { userId_kind_anilistId: { userId, kind, anilistId } },
        create: { userId, kind, anilistId, mediaId: anilistId },
        update: {},
      });
    } else {
      const snapshot = { name: target.name, image: target.image };
      await prisma.favorite.upsert({
        where: { userId_kind_anilistId: { userId, kind, anilistId } },
        create: { userId, kind, anilistId, ...snapshot },
        update: snapshot,
      });
    }

    revalidatePath(targetPath(target));
    if (ctx.user.username) revalidatePath(routes.profile(ctx.user.username));

    return { favorite };
  });
```

```tsx
/**
 * Le cœur : une œuvre, un personnage ou un staff dans mes favoris.
 *
 * **`useOptimistic` et pas `useState`**, pour la raison de `volume-board.tsx` : l'état suit le clic

 * Trois appelants dès sa création (fiche, personnage, staff), donc dans `features/favorites/`.

export function FavoriteButton({
  target,
  initial,
}: {
  target: FavoriteTarget;
  /** Ce que la base dit, lu par le parent serveur. */
  initial: boolean;
}) {
  const [favorite, setOptimistic] = useOptimistic(initial);

  const { executeAsync } = useAction(setFavorite, {
    onError: ({ error }) =>
      toast.error(
        error.serverError ?? "Le favori n'a pas pu être enregistré. Réessayez.",
      ),
  });

  const label = favorite ? "Retirer de mes favoris" : "Ajouter à mes favoris";

  return (
    <Tooltip>
      <TooltipTrigger asChild>
        <Button
          aria-label={label}
          aria-pressed={favorite}
          onClick={() =>
            startTransition(async () => {
              const next = !favorite;
              setOptimistic(next);
              await executeAsync({ target, favorite: next });
            })
          }
          size="icon"
          variant="outline"
        >
          <HeartIcon className={cn(favorite && "fill-current")} />
        </Button>
      </TooltipTrigger>
      <TooltipContent>{label}</TooltipContent>
    </Tooltip>
  );
}
```
